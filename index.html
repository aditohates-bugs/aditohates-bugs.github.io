Sync programming:- Does task 1 by 1(completes task completely then moves on)
Async programming:- While doing one task when we have to fetch foreign data/input that takes time we can say so the program moves on the next task(abuse the cpu never let it rest).

Async Programming

Fundamental terms of async programming: event loop, coroutines, async, await

Basic Structure to use

Event Loop >> Manager of a group project(ususally just the main thread)
Co-routines >> Employees who dont work without instructions and pause when laptop updating/ data taking time to arrive>>await
Await >> Awaiting for data/input to arrive>> the manager can start other tasks/find other employees to work on other tasks while waiting for the data to arrive on present guy

Event loop

Keeps cycling through tasks, never lets the CPU sit idle waiting for data, it switches to next tasks(basically abuses the CPU)

Coroutines

Using the async def we can make a coroutine. These are like tasks that need to be in the loop in order to function.They are basically private objects for the library(asyncio)

In Python, only one thread can work at a time

You get Concurrency (switching tasks quickly), not Parallelism (doing tasks simultaneously)

Cooking Dinner Analogy

One Chef. He chops onions, then stops to stir the soup, then goes back to chopping. He is doing multiple things, but only one at a time.
Two Chefs. One chops onions while the other stirs the soup. They work at the exact same time

Python: Uses Heavy Threads limited by the GIL. Great for waiting tasks (like downloading files) but slow for heavy math.
C++: Uses OS Threads. They are powerful and run purely in parallel, but they are complex to manage manually.
Golang: Uses Goroutines. These are "super-lightweight" threads. You can run thousands of them easily, and they automatically use all CPU cores
